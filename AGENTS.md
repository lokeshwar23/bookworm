## Critical Gotchas

### Server Components must NOT self-fetch
Server Components (e.g. `app/(store)/page.js`) must query the DB directly via `lib/db.js`, never via `fetch('/api/...')`. Self-fetching causes infinite hangs on startup because the server isn't ready when the page renders.

```js
// ✅ Correct — direct DB call in Server Component
import sql from '@/lib/db';
const books = await sql`SELECT * FROM books LIMIT 8`;

// ❌ Wrong — self-fetch in Server Component hangs forever
const res = await fetch('http://localhost:3000/api/books');
```

### `package.json` has `"type": "module"`
All `.js` files use ES module syntax (`import`/`export`). No `require()` or `module.exports`.

### Dynamic filters use `sql.unsafe()` not tagged template literals
`lib/bookQueries.js` builds parameterised queries with `sql.unsafe(query, params)` because column names and ORDER BY clauses are dynamic. Tagged template literals (`sql\`...\``) are used everywhere else.

### Two separate cookie systems
- **Auth:** `auth_token` cookie — HTTP-only, SameSite=strict, set via `lib/auth.js` → `getAuthCookieOptions()`
- **Guest cart:** `cart_session_id` cookie — SameSite=lax, set via `lib/cartSession.js` → `getOrCreateSessionId(request, response)`

Never cross-use these helpers.

### `getCurrentUser()` reads cookies server-side only
`lib/auth.js` `getCurrentUser()` uses Next.js `cookies()` from `next/headers` — only callable in Route Handlers and Server Components. Client components use `AuthProvider` context (`components/AuthProvider.jsx`).

### Payment flow is two-step
1. `POST /api/checkout/create-order` → creates DB order with status `pending`, returns Razorpay order ID
2. `POST /api/checkout/verify-payment` → verifies HMAC signature (skipped when `PAYMENT_MODE=mock`), sets status `confirmed`

Never confirm an order without going through verify-payment.

### `PAYMENT_MODE=mock` bypasses Razorpay entirely
Set in `.env.local`. When active, `lib/razorpay.js` `isMockMode()` returns `true` — no real credentials needed. The client reads `NEXT_PUBLIC_PAYMENT_MODE` and shows `MockPaymentModal` instead of the Razorpay popup.

### `useSearchParams()` requires `<Suspense>` wrapper
Any client component using `useSearchParams()` must be wrapped in `<Suspense>` at the page level or the build fails with a prerender error. See `app/(store)/catalogue/page.jsx` for the pattern.

## DB Schema Key Rules
- All IDs are `UUID` generated by `gen_random_uuid()` (requires `pgcrypto` extension — applied by `schema.sql`)
- `book_format` and `order_status` are PostgreSQL ENUM types — cast explicitly: `$1::book_format`
- Gift points: earn `floor(total / 10)` per order, redeem 1 point = ₹1. Deducted at `create-order`, awarded at `verify-payment`
- Free delivery when `subtotal >= 500`, else ₹50 — computed in `lib/orderUtils.js` `computeTotals()`

## File Conventions
- Route Handlers: `app/api/**/route.js`
- Store pages: `app/(store)/**/page.jsx` (client) or `page.js` (server)
- Auth pages: `app/(auth)/**/page.jsx`
- All components: `components/*.jsx` with `'use client'` at top
- All lib utilities: `lib/*.js` (server-side only, no `'use client'`)
